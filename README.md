# Zombie Apocalypse SMP

Minecraft 1.21.1 + NeoForge 기반의 멀티플레이 좀비 아포칼립스 모드 프로젝트입니다.

## 개발 환경
- Java 21 (JDK)
- Minecraft 1.21.1
- NeoForge 21.1.264
- Gradle / ModDevGradle

## 프로젝트 목표
- 유튜버 20~30명 규모의 시즌제 PvPvE 생존 서버
- 감염, 좀비 AI, 거점 약탈, 총기, 차량 및 경제 시스템
- 8,000 x 8,000 블록 월드와 좀비 대이동 이벤트

## 소리 감지 규칙 (초기 밸런스)

| 행동 | 감염자 탐지 반경 |
| --- | ---: |
| 웅크리고 이동 | 2.5블록 |
| 일반 걷기 | 7블록 |
| 전력 질주 | 16블록 |
| 문·덫문·울타리 문 여닫기 | 12블록 |
| 블록 파괴 | 16블록 |
| 블록 설치 | 10블록 |
| TNT 등 폭발 | 48블록 |
| `/za_noise` 테스트 명령어 | 24블록 |

- 발소리는 서버에서 **8틱마다 위치 변화를 샘플링**해 발생시키는 근사 방식입니다. 단순 음향 재생에 반응하는 것은 아닙니다.
- 달리지 않고 웅크려 이동하면 감지 반경이 작아집니다. 땅에 서서 움직이는 경우만 대상이며 수영·비행·탑승 중에는 발생시키지 않습니다.
- 문·덫문·울타리 문은 **실제로 열림 상태가 바뀐 경우에만** 소리 신호를 보냅니다. 플레이어가 직접 우클릭해서 상태가 바뀌는 경우를 감지하며, 레드스톤으로만 열리는 경우는 이번 버전 범위 밖입니다.
- 실제 AI는 대상 플레이어를 이미 발견하면 추격·공격을 우선합니다. 길 찾기 장애물이 있으면 소리 위치에 도달하지 못할 수도 있습니다.
- 감염자는 서버가 보내는 알림에만 반응합니다. **실제 마이크, 총소리, 일반 게임 음향 전체를 듣지는 않습니다.**

## 휴대용 경보기 아이템 테스트

첫 실사용 아이템 **휴대용 경보기 (시험용)** 를 추가했습니다. 총기는 아직 없으므로 큰 소리를 내는 간단한 테스트 도구입니다.

- 획득(치트 허용): `/give @s zombieapocalypse:noise_emitter`
- 손에 든 상태로 우클릭하면 **플레이어 위치에서** 모루 소리와 음표 입자가 발생합니다.
- 반경 **40블록** 안의 커스텀 감염자에게 소리 위치를 조사하라는 신호를 보냅니다.
- **3초(60틱) 재사용 대기시간**, 무제한 사용(현재는 테스트용)
- 외형은 임시로 기본 화염구 아이콘을 사용합니다. 추후 전용 모델을 만들 수 있습니다.
- 플레이어 근처에서 소리가 나기 때문에 감염자를 **자기 쪽으로 유인**합니다. 던지는 장치는 아직 아닙니다.

**테스트 방법:** 게임을 종료한 뒤 GitHub Desktop에서 Pull 하고 개발용 클라이언트를 다시 실행합니다. 크리에이티브 테스트 월드에서 `/summon zombieapocalypse:infected ~25 ~ ~`로 감염자를 소환한 다음 `/give @s zombieapocalypse:noise_emitter`로 아이템을 받습니다. 감염자와 약 25블록 떨어진 위치에서 경보기 아이템을 우클릭하면, 기존 발소리 탐지 거리(최대 16블록)보다 먼 곳에서도 감염자가 조사하러 와야 합니다.

## 인게임 테스트

1. GitHub Desktop에서 `Fetch origin → Pull origin` 후 개발용 마인크래프트를 실행하세요.
2. 치트 허용 크리에이티브 월드에서 `/summon zombieapocalypse:infected ~12 ~ ~`로 감염자를 소환하세요. (크리에이티브에서는 기존 시각 추격 AI가 개입하지 않아서 소리 테스트가 편합니다.)
3. **달리기**: 감염자와 약 12블록 거리에서 달려 보세요. 감염자가 발소리 위치를 조사하는지 확인하세요.
4. **일반 걷기**: 감염자와 5~7블록 거리에서 걸어 보세요.
5. **웅크리기**: 약 6블록 이상 떨어져 웅크려 이동하면 발소리만으로는 감지되지 않아야 합니다. 주변 블록 파괴·설치로 발생하는 소리는 별개입니다.
6. **문**: 감염자와 10블록 정도 떨어진 상태에서 나무문을 직접 열고 닫아 보세요.
7. 구분이 어려우면 `/za_noise`로 기존 명령어 감지가 유지되는지 비교 테스트하세요.

테스트 월드의 다른 몹, 장애물, 기존 탐색 위치 등에 따라 동작이 달라질 수 있습니다. 테스트에서 이상이 발견되면 이벤트 감지 및 동작 방식을 조정합니다.

## 🔫 G17 권총 프로토타입 (v0.2.0)

이번 버전은 **작동하는 원거리 무기 프로토타입**입니다. Glock 17에서 이름과 17발 탄창을 가져온 게임 아이템이며, 실제 총기 3D 모델·장전 애니메이션·탄도 물리는 아직 구현하지 않았습니다.

| 기능 | 게임 내 설정 |
| --- | --- |
| 발사 | **좌클릭** (G17 장착 시 일반 공격 및 채굴 대신 발사) |
| 재장전 | **R키** (조작 설정에서 변경 가능) |
| 탄창 크기 | 17발 |
| 기본 탄창 | 새 권총에 17발 장전 |
| 탄약 | `zombieapocalypse:pistol_ammo` |
| 명중 방식 | **실제 고속 탄환 엔티티** (초당 약 80블록, 중력 없음, 벽·몹 충돌) |
| 피해량 | 명중 시 7 기본 피해량(상대 방어력 영향 가능) |
| 발사 간격 | 6틱 (0.3초) |
| 재장전 대기시간 | 25틱 |
| 총성 감지 거리 | 커스텀 감염자 기준 64블록 |

- **권총과 탄약은 아직 획득용 제작법/루팅이 없습니다.** 치트 명령어로 지급해야 합니다.
- **서버에서만** 명중, 탄약 소비, AI 소음 전파를 처리합니다. 각 권총의 장탄 수는 아이템 데이터에 저장됩니다.
- 서바이벌에서 재장전하면 인벤토리의 권총 탄약을 실제 소비합니다. 크리에이티브에서는 재장전할 때 탄약을 소비하지 않습니다.
- 이 단계는 플레이어와 몬스터 모두 피격 가능한 테스트용 시스템입니다. PVP 밸런스, 커스텀 총상 유형, 무기 부착물 등은 나중에 개발합니다.
- 권총 아이콘은 임시로 기본 망원경 텍스처를, 탄약 아이콘은 철 조각 텍스처를 사용합니다.

### 인게임 테스트 명령어

```mcfunction
/give @s zombieapocalypse:g17_pistol
/give @s zombieapocalypse:pistol_ammo 64
/summon zombieapocalypse:infected ~12 ~ ~
```

1. 마인크래프트를 종료하고 GitHub Desktop에서 **Fetch origin → Pull origin** 후 IntelliJ의 `.\gradlew.bat runClient`로 실행합니다.
2. 치트가 활성화된 **크리에이티브 테스트 월드**에서 위 명령어 3개를 사용합니다.
3. G17 권총을 손에 들고 좀비를 바라보며 **좌클릭**하면 발사 소리와 시각 효과가 나고 좀비가 피해를 입어야 합니다.
4. 좌클릭을 여러 번 눌러 17발을 소비합니다. 핫바 위 행동 표시줄에서 남은 탄창 수를 확인합니다.
5. **R키**를 누르면 탄창을 채웁니다. 서바이벌 모드에서 재장전하면 `pistol_ammo`가 실제 소비되는지 확인합니다.
6. 20~40블록 떨어진 다른 감염자가 발포 위치를 조사하는지도 확인합니다. 시야에 플레이어가 들어오면 기존 추격 AI가 우선합니다.

**중요:** 실제 마이크 소리, 전용 탄피·총기 모델·재장전 애니메이션은 아직 연결하지 않았습니다.

## G17 조작·탄환 업데이트

이전의 우클릭/Shift+우클릭 및 히트스캔 조작은 폐기했습니다.

- **좌클릭**: 발사. 권총을 주 손에 쥐었을 때 기본 마인크래프트 근접 공격/블록 파괴를 막고 서버에 발사 요청을 보냅니다. 다른 아이템은 원래처럼 작동합니다.
- **R키**: 재장전. `설정 → 조작`에서 키를 변경할 수 있습니다.
- **투사체**: 맞는 순간을 계산하는 즉시 명중 판정 대신, `zombieapocalypse:pistol_bullet` 엔티티가 실제 월드를 빠르게 이동합니다. 초당 약 80블록의 초기 속도로 발사되어 몬스터·플레이어·벽에 부딪혀 사라집니다.
- 기존 **17발 탄창**, **탄약 소비**, **발사·재장전 쿨다운**, **64블록 총성 감지**는 그대로 유지됩니다.
- 이 단계의 총알은 보기 편하도록 임시 탄약 아이콘으로 표시되며 중력 낙하가 없습니다. 충돌 및 속도 밸런스는 인게임 테스트 결과에 따라 수정합니다.

**테스트:** 기존처럼 `/give @s zombieapocalypse:g17_pistol`, `/give @s zombieapocalypse:pistol_ammo 64`, `/summon zombieapocalypse:infected ~12 ~ ~`로 준비한 뒤 좌클릭으로 발사하고 R로 재장전해 보세요. 벽 뒤의 좀비에게 총알이 막히는지도 확인해주세요. 가까이 있거나 블록을 바라보고 쏘는 경우, 발사 클릭이 일반 채굴/근접 공격으로 처리되지 않는지도 확인합니다.

## G17 정조준(ADS)·반동·명중률 업데이트

- **우클릭을 누르고 있기**: G17을 주 손에 든 동안 정조준 상태로 들어갑니다. 화면 FOV가 부드럽게 약 **70%**로 줄어듭니다. 버튼을 놓거나 총을 바꾸면 원래 시야로 돌아옵니다. 현재는 조준 UI/3D 가늠쇠 없이 시야 확대만 구현합니다.
- **좌클릭**: 정조준 중에도 기존처럼 발사합니다. 기존 17발 탄창, R 재장전, 실제 고속 투사체, 좀비의 64블록 총성 인식은 유지합니다.
- **반동**: 서버가 실제 총알 생성에 성공한 경우에만 발사자 화면을 위쪽으로 튀게 하고, 좌우로 약간 흔들리게 합니다. 정조준 중에는 반동이 더 작습니다.
- **명중률**: 탄환의 방향에 실제 편차가 생깁니다. 서버가 플레이어 자세 및 이동 상태와 ADS 상태를 검사하여 탄환 퍼짐을 정합니다. 단위는 게임 내 발사 오차(각도)입니다.

| 상태 | 초기 탄 퍼짐(대략) |
| --- | ---: |
| 정지 + 정조준 | 0.3° |
| 웅크려 정지 + 정조준 | 0.18° |
| 이동 + 정조준 | 0.95° |
| 웅크려 정지 + 비조준 | 1.6° |
| 서서 정지 + 비조준 | 2.4° |
| 이동 + 비조준 | 3.4° |
| 전력질주 | 5.0° |
| 공중 | 5.5° |

정조준 정보는 클라이언트에서 서버로 전송되지만, 서버가 **실제로 G17을 들었는지 확인**하고 갱신이 끊긴 조준 상태는 자동 만료합니다. 따라서 단순히 클라이언트 표시만 달라지는 명중률 보정은 아닙니다.

### 수동 테스트

1. Minecraft 종료 → GitHub Desktop `Fetch origin → Pull origin` → IntelliJ `.\gradlew.bat runClient`.
2. 치트 허용 크리에이티브 테스트 월드에서 `/give @s zombieapocalypse:g17_pistol` 및 `/give @s zombieapocalypse:pistol_ammo 64` 입력.
3. G17을 들고 **우클릭 길게 눌러 화면이 확대되는지**, 놓으면 원상 복귀하는지 확인.
4. **좌클릭으로 발사**해서 위쪽 반동을 확인하고, 우클릭 ADS 중에는 반동이 더 작은지 확인.
5. 15~25블록 거리에 여러 블록의 타깃(또는 좀비)을 준비해 서서 비조준, 정조준, 이동·질주 사격을 비교합니다. 퍼짐은 무작위이므로 여러 발을 쏘며 비교하세요.
6. **R 재장전**, 17발 탄창, 탄환 벽 충돌, 감염자 총성 반응 등 기존 기능도 점검해 주세요.

**주의:** G17을 들었을 때 우클릭은 ADS로 사용되므로 문이나 상자와 상호작용하려면 잠시 다른 아이템을 들어야 합니다. 기본 게임 이동 속도 자체를 늦추는 조준 페널티나 무기 3D 모델, 조준 가늠쇠는 아직 없습니다.

## G17 전용 HUD (개발용)

G17을 **주 손에 들었을 때만** 화면 **왼쪽 아래, 핫바 왼편**에 표시되는 미니멀 총기 HUD를 추가했습니다. 일반 아이템을 들거나 인벤토리를 열면 표시되지 않습니다. F1의 게임 HUD 숨김 설정도 따릅니다.

HUD에서 읽는 데이터:
- **탄창 수 / 17발**: 권총의 `CUSTOM_DATA`에 저장된 실제 남은 장탄 수를 표시합니다. 17개의 작은 막대로 남은 탄 수를 볼 수 있고 4발 이하일 때 빨간색으로 경고합니다.
- **예비 탄약**: 현재 플레이어의 인벤토리에 있는 `zombieapocalypse:pistol_ammo` 개수를 합산합니다. 크리에이티브 모드에서는 탄약 없이도 재장전할 수 있으므로 `∞`로 표시합니다.
- **발사 모드**: `반자동 / SEMI` 로 표시합니다. 현재 G17은 반자동만 구현되어 있으며 다른 발사 모드 변경은 제공하지 않습니다.
- **재장전 상태**: 서버에서 재장전에 성공했다는 응답을 받은 경우에만 약 38틱(1.9초) 동안 **재장전 후딜 / RELOAD RECOVERY**와 진행 막대를 표시합니다. 현재 탄약은 R 입력 시 즉시 채워지고 이후 25틱 발사 제한이 적용됩니다. 추후 재장전 애니메이션을 제작할 때 실제 지연 재장전으로 바꿀 수 있습니다.
- 탄창이 0발이면 `탄창 비어 있음 / MAG EMPTY`, 그 외에는 `발사 준비 / READY`를 표시합니다.

UI는 게임 렌더링에서만 작동하며, 총알의 발사·피격·탄약 소비는 기존과 같이 서버에서 처리합니다. 게임의 FOV 조준, 카메라 반동, 탄퍼짐 등 이전 동작은 변경하지 않았습니다.

## G17 1인칭·3인칭 겨누기 자세 및 총구 탄환 (프로토타입)

실제 사용자 인게임 사진을 기반으로 **기존 G17 3D 모델은 유지**하고 손·팔 연출을 추가했습니다.

- **총구 탄환:** 총알 엔티티를 눈앞 중앙이 아닌 **카메라 방향 앞쪽·주 사용 손 방향으로 오프셋된 총구 위치**에서 생성합니다. 화면 조준점의 블록까지 직선을 계산해 탄환의 방향을 맞추되 **데미지는 여전히 실제 날아가는 투사체의 충돌에서만** 발생합니다. 근거리 벽과의 교차도 확인합니다.
- **총구 효과:** 총알 생성 위치에서 작은 화염·연기 입자를 재생합니다.
- **모델 표시:** 1인칭 모델을 약간 작게 조정해 팔과 함께 보일 공간을 확보합니다. 3인칭·인벤토리 모델은 유지합니다.
- 발사 간격(6틱), 장탄 수(17발), 탄약 소비, ADS 탄 퍼짐, 카메라 반동, 소음 AI, HUD는 수정하지 않습니다.

## G17 1인칭 화면 밖 총기 / 거대 팔 렌더링 버그 수정

실제 인게임 피드백: 이전 첫 시도에서는 일반 자세의 G17이 화면 위로 튀어나가고, ADS에서는 분리된 팔이 지나치게 커져 화면을 가렸습니다.

원인과 수정:
- 이전 `G17ViewRenderer`가 `RenderHandEvent`를 취소하고, 실제 아이템과 팔을 직접 렌더했습니다. **아이템 JSON 표시 변환과 추가 PoseStack 변환이 중첩**된 상태에서 1인칭 화면에 잘못 배치되었습니다.
- 플레이어 팔을 `renderRightHand/renderLeftHand`로 그릴 때 필요한 **마인크래프트 기본 팔 모델 좌표계 변환**이 누락되어 커다란 팔이 떠 있었습니다.
- 이번에는 **기본 아이템 렌더링을 취소하지 않고 유지**합니다. 원래 G17을 그리는 경로를 그대로 사용하며, 별도의 총기 중복 렌더링을 없앴습니다.
- 주 손의 팔은 바닐라의 팔 모델 좌표 보정 수식을 적용해 아래쪽에 표시하고, **평상시에는 주 손만**, **정조준할 때는 보조 손이 비어 있는 경우에만 반대 팔을 추가**합니다.
- 정조준 위치 보정은 NeoForge `IClientItemExtensions.applyForgeHandTransform`에서 **한 번만** 적용하고 기존 기본 장착/휘두르기 동작은 보존합니다.
- 모델의 1인칭 JSON 표시 값은 **중립적인 이동 및 0.22배율**로 정리했습니다. 3인칭 자세, 총구 발사, 탄 퍼짐, 반동, HUD는 변경하지 않습니다.

**인게임 재검증:** 게임 종료 후 GitHub Desktop `Fetch origin → Pull origin`, `.\gradlew.bat runClient` 실행. G17 기본 1인칭에서 권총과 한쪽 팔이 정상적으로 보이는지, 우클릭 ADS에서 양팔 및 권총이 프레임 안에 들어오는지 확인합니다. F5 3인칭 겨누기, 좌클릭 탄환 발사, R 재장전 및 HUD도 함께 확인합니다. 만약 특정 GUI 크기에서 총 위치가 완벽하지 않으면 새 1인칭 스크린샷으로 미세조정합니다.

## G17 철가늠쇠 정조준(ADS) 화면 정렬 (두 번째 수정)

실제 사용자 스크린샷에서 일반 시점에서는 G17이 화면 너무 아래에 있고,
ADS에서는 총이 사라지고 팔만 보이는 증상을 확인했습니다.

**수정 핵심**
- 원본 Blockbench 총열의 +Z 방향을 1인칭 모델 표시에서 180도 회전해 **카메라 전방(-Z)** 으로 맞췄습니다. 3인칭·인벤토리 모델의 표시 설정은 건드리지 않았습니다.
- `G17ClientExtensions`에서 마인크래프트가 아이템에 추가로 적용하던 일반 장착 변환을 **건너뛰고(`return true`)**, G17만을 위한 명시적인 1인칭 카메라 좌표를 적용합니다.
- ADS에서 뒷가늠쇠 근처의 좌표(원본 모델 약 x=1, y=21, z=-9)가 카메라 중앙에 오도록 모델 크기 0.25배를 기준으로 직접 보정했습니다.
- 평상시에는 총이 오른쪽 아래에 보이고, 우클릭 정조준 시 가늠쇠가 중앙에 위치하도록 부드럽게 보간합니다.
- 팔은 정조준 중에도 남기되 양쪽 아래로 내리고 조금 작게 하여 가늠쇠가 가려지지 않도록 했습니다. 3인칭 겨누기 자세는 이전 그대로입니다.
- **총구 근처 고속 투사체, 소음 감지, 탄퍼짐, 반동, HUD, R 재장전 로직은 변경하지 않았습니다.**
- CI에는 총열 전방 방향과 뒷가늠쇠의 대략적인 수학적 정렬을 검사하는 단언을 추가했습니다. 이는 **인게임 시각 확인을 대신하지 않습니다.**

### 인게임 확인

1. 게임 완전 종료 → GitHub Desktop `Fetch origin → Pull origin` → IntelliJ `.\gradlew.bat runClient`.
2. G17 장착 후 **일반 1인칭**에서 권총과 주 손이 화면 오른쪽 아래에 자연스럽게 표시되는지 확인.
3. **우클릭 길게 눌러 ADS**에서 총열이 앞쪽을 향하고 뒷가늠쇠가 화면 정중앙에 오며 양팔이 아래에서 받치는지 확인.
4. **우클릭을 놓으면** 자연스럽게 일반 자세로 복귀하는지 확인.
5. F5 **3인칭**, 좌클릭 발사 및 탄환 충돌, R 재장전·HUD·반동을 함께 간단히 점검.
6. 모델이 여전히 조금 높거나 아래로 보이면 일반/ADS **스크린샷 두 장**으로 보정 좌표를 미세조정합니다.

## G17 1인칭 총구가 플레이어를 향하던 문제 (방향 반전 수정)

인게임 테스트에서 ADS 정중앙에 **총구 구멍이 보이는 현상**이 확인되었습니다.
원본 Blockbench 모델의 총구는 **모델 -Z** 방향, 뒷가늠쇠/손잡이는 **+Z** 방향인데,
직전 업데이트에서 1인칭 모델을 Y축으로 180도 회전한 것이 원인이었습니다.

- `g17_pistol.json`의 **1인칭 모델 회전만 180° → 0°**로 복원합니다.
- `G17ClientExtensions`에서 앞뒤가 다시 바뀐 상태에 맞게 **뒷가늠쇠 X축 ADS 보정**을 반대로 조정합니다.
- 일반 자세의 화면 위치, 크기, ADS 전환, 팔 자세, 3인칭 모델, 서버 발사 로직과 총구 파티클, 탄퍼짐, HUD는 그대로 유지합니다.
- CI 검증은 실제 **-Z 총구 / +Z 뒷가늠쇠 방향**과 화면 중앙 기준 좌표를 검사합니다.

### 테스트
게임 종료 → GitHub Desktop `Fetch origin → Pull origin` → `.\gradlew.bat runClient`.
G17 우클릭 정조준 때 **총구의 원형 구멍 대신 뒷가늠쇠와 상단 슬라이드**가 보이고,
총열이 십자선 방향으로 멀어지는지 확인합니다. 좌클릭 사격·R 재장전·3인칭·HUD도 짧게 확인합니다.
**자동 빌드는 실제 렌더링을 확인하지 않으므로**, 총의 앞뒤를 인게임 스크린샷으로 최종 검증해야 합니다.

## G17 총기 파지 및 오리지널 1인칭 애니메이션 (TaCZ 구조 참고)

TaCZ `tacz-1.20.1-1.1.8-hotfix2.jar`를 **작동 원리 분석 용도**로 확인했습니다. 해당 JAR는 **Minecraft 1.20.1 Forge 버전**으로, 우리 프로젝트의 **Minecraft 1.21.1 NeoForge 모드에 포함하거나 런타임 의존성으로 추가하지 않았습니다.**

이번 구현은 **우리 프로젝트만의 `client/G17AnimationState.java`** 에 원본 수학적 모션 곡선을 작성하고, 기존 G17 렌더링에 연결한 첫 번째 버전입니다.

- **총 장착:** 핫바에서 G17을 선택하면 총과 주 팔이 약 10틱 동안 아래쪽에서 자연스럽게 올라옵니다.

- **재장전:** R키 요청을 서버에서 성공 처리한 경우에만 약 **38틱(1.9초)** 동안 총을 내리고 기울였다가 복귀시키고, 빈 보조 손이 탄창 쪽으로 이동하는 모션을 재생합니다.
- **정조준:** 기존에 인게임 테스트로 확인한 **뒷가늠쇠 중심 및 올바른 총구 방향을 유지**합니다. 재장전 중에는 카메라 확대·손·총이 자연스럽게 내려갔다가 복귀합니다.

- **3인칭:** 이전 테스트에서 구현했던 양손 겨누기 자세(`CROSSBOW_HOLD`)는 그대로 둡니다.
- **서버 안정성:** 명중·탄퍼짐·탄약 소비·물리 탄환·총구 파티클·소음 AI 로직과 HUD 위치 및 크기는 바꾸지 않았습니다.

## G17 총기 모델-손 위치 동기화 및 슬라이드/탄창 가시적 애니메이션 (두 번째 개선)

TaCZ JAR의 **구조적 원리**를 분석해 참고했습니다: 1인칭 전용 손 뼈대(오른손/왼손의 그립 기준), 움직이는 슬라이드, 움직이는 탄창, 별도 발사·장전 상태 머신, 프레임 보간. 이 디자인 개념을 우리 게임 버전에 맞춰 **독립 구현**했습니다. TaCZ의 실제 코드, 오디오, 모델링, 키프레임/애니메이션 JSON을 복사하지 않았습니다.

**이전 구현의 문제:** 손의 카메라 좌표가 총 손잡이와 일치하지 않아 어색하고, 총 자체의 후퇴도 짧아 눈에 잘 띄지 않았습니다. 재장전은 25틱으로 빠르고 모델 내부 파츠가 움직이지 않았습니다.

### 새로 구현된 연출

- **그립 중심 양손 배치:** 주 손과 보조 손이 손잡이/뒷가늠쇠 아래로 가까워지도록 1인칭 손 위치를 재설정. ADS에서는 양손이 중앙 하단으로 모이고, 힙파이어 시에는 오른손(왼손잡이는 왼손)만 표시합니다.
- **발사 시 슬라이드 실제 후퇴:** 기존 Blockbench 모델의 슬라이드·가늠쇠를 별도 JSON 모델 상태로 만들어 실제 `+Z`(총구 반대쪽)으로 이동합니다. 게임에서 **잠깐 완전 후퇴 → 부분 복귀 → 원위치**가 보입니다.
- **재장전 시 탄창 탈착:** 기존 모델의 베이스플레이트와 새로 작성한 간단한 폴리머 탄창 큐브를 함께 움직이는 두 모델 상태를 추가해 **탄창이 아래로 빠졌다 다시 들어가는 시각 효과**를 표시합니다.
- **재장전 동작 38틱(1.9초):** 서버 발사 제한 시간, 총 움직임, 보조 손의 탄창 접근, HUD의 재장전 막대를 같은 길이로 일치시켰습니다. 현재 탄약 이동 자체는 R키가 서버에서 승인되면 즉시 적용되고, 1.9초 후 사격 가능해집니다.
- **반동 강조:** 전체 총/주 손의 짧은 후퇴와 회전이 이전보다 분명하게 보입니다.
- **프레임 보간:** `RenderHandEvent.getPartialTick()`으로 팔 움직임을 부드럽게 샘플링합니다. 총기 모델의 슬라이드·탄창 변형은 아이템 프로퍼티 기반의 몇 개 정적 프레임을 전환하는 방식입니다.
- **1인칭 전용:** `ItemProperties`가 로컬 플레이어의 1인칭 G17에서만 모델 상태를 변경하므로, 인벤토리/3인칭 아이템 외형은 기존처럼 유지됩니다.

**범위/한계:** 실제 TaCZ 같은 전체 본 스켈레톤/손가락 관절 애니메이션을 동일하게 복제한 것은 아닙니다. 손은 바닐라 플레이어 팔을 사용하며, 탄창·슬라이드는 일부 모델 큐브의 자세를 바꾼 프레임 변형입니다. 발사, 피격, 감염자 소음 감지 등의 로직은 그대로 유지했습니다.

### 인게임 확인 방법

1. Minecraft 완전 종료 → GitHub Desktop `Fetch origin → Pull origin` → IntelliJ `.\gradlew.bat runClient`.
2. G17 장착 후 **우클릭 ADS**에서 손이 총의 손잡이 아래에 붙어 있는지, 뒷가늠쇠와 십자선이 여전히 일치하는지 확인합니다.
3. 1인칭으로 **좌클릭 발사**하면 슬라이드가 짧게 후퇴하는지 확인합니다. 천천히 보려면 연속 촬영/영상이 더 효과적입니다.
4. 여러 발 발사하고 **R 재장전**: 총이 내려가고 기울며 보조 손이 접근하고 **탄창 바닥이 내려갔다 올라오는지** 확인합니다.
5. 발사·재장전 중 HUD 탄약 수가 정상이고 재장전 막대가 약 **1.9초** 표시되는지 확인합니다.
6. 손이 총 손잡이와 겹치거나 떨어져 보이면 **일반/ADS/재장전 3장의 스크린샷** 또는 짧은 영상으로 위치를 확인합니다.
7. 마인크래프트 게임 메뉴에서 1인칭/3인칭 전환, 좌·우 손잡이 설정, F1 UI 숨김이 기존과 동일하게 작동하는지 점검합니다.

## G17 1인칭 손 파지/ADS/장전 위치 수정 (영상 피드백)

2026-10-28 사용자가 제공한 약 24초간의 실제 플레이 영상을 확인했습니다. 일반 자세에서 오른손과 총 손잡이 사이에 눈에 띄는 간격이 있었고, **우클릭 ADS에서는 총만 화면 중앙으로 올라왔지만 오른손은 오른쪽 아래에 남는 현상**이 있었습니다. 재장전 중 보조 손도 화면 아래쪽에 머물러 탄창에 접근하는 동작이 거의 보이지 않았습니다.

이번 수정에서는 **총 모델의 상대 좌표가 아닌 실제 카메라에 적용되는 G17 위치를 기준으로 손 위치를 추적**합니다:

- **하나의 원점 사용:** `G17ClientExtensions.calculatePose()`가 매 프레임 장착·발사·재장전·ADS를 포함하는 실제 총기 카메라 좌표(x/y/z + 회전)를 계산합니다. 해당 좌표를 **1인칭 총 모델 렌더링**과 **`G17ViewRenderer`의 양손 파지**가 함께 사용하도록 연결했습니다.
- **일반 파지:** 오른손/왼손잡이 주 사용 손을 손잡이 쪽으로 안쪽 이동시킵니다. 사용 중인 스킨 텍스처와 기존 손 렌더링 파이프라인을 그대로 이용합니다.
- **우클릭 ADS:** 총을 중앙으로 올릴 때 주 사용 손과 빈 보조 손도 동일한 총기 좌표 변화를 따라 올라오고 안쪽으로 모입니다. 손이 가늠쇠를 가리지 않도록 손목 위치를 뒷가늠쇠 아래로 둡니다.
- **R 재장전:** 재장전 타임라인에서 보조 손이 총의 탄창 쪽으로 **아래가 아니라 위로 약 0.34 카메라 좌표만큼 이동하도록** 수정했습니다. 주 사용 손은 기울어지는 G17을 계속 따라갑니다.
- **동기화:** 총과 손은 동일한 샘플링 보간 프레임, 장착 진행도 및 기존 38틱 재장전 상태를 사용하며 손에 별도로 장착 오프셋을 두 번 적용하지 않습니다.
- **유지:** 총구가 세계를 향하는 방향(-Z), 뒤 가늠쇠 중심, 기존 원본 모델/슬라이드/탄창 모델 상태, 3인칭 양손 자세, 탄약·물리 탄환·총성/AI·HUD 및 서버 로직은 변경하지 않았습니다.

**주의:** Minecraft 기본 플레이어 팔 메시를 활용하는 방식이므로 TaCZ처럼 독립 손가락 뼈대가 있는 실제 손가락 파지는 아직 불가능합니다. GitHub 자동 빌드로 코드 연결이 성공해도 실제 화면의 손 위치는 인게임 영상으로 확인해야 합니다.

## G17 1인칭 오른손·왼손 파지 리그 근본 수정 (2026-10-29)

플레이어가 보낸 `20261028_235956.mp4` 영상에서 **총이 팔에 묻혀 보이고, 주 사용 오른손이 왼손처럼 보이며, ADS에서 오른손이 너무 왼쪽으로 빠지는 문제**를 확인했습니다.

TaCZ 1.20.1 JAR의 손 렌더링 구조를 분석한 결과, TaCZ는 별도의 **오른손/왼손 기능성 렌더러와 총 모델의 애니메이션 기준 노드**를 가지고 있어 각 손이 움직이는 총기 기준점에 붙습니다. 이번 G17 구현은 그 **일반적인 리그 원리**를 독자적으로 적용했습니다. TaCZ 코드·모델·사운드·키프레임·애니메이션 리소스는 복사하거나 프로젝트에 포함하지 않았습니다.

이전 렌더러 문제:
- 총은 `HeldPose`를 기준으로 이동했지만 각 손은 `held.x/y/z + 절대 화면 손목 좌표`로 따로 배치되었고, **총의 Y/X/Z 회전을 전부 따르지 못했습니다**.
- 일반 오른손의 좌표가 오른쪽이 아니라 **왼쪽으로 보정되는 부호**였으며, ADS에서 손이 가늠쇠를 가렸습니다.
- 큰 원본 팔 모델을 표시하면서 보조 손이 총의 슬라이드 앞에 겹쳤습니다.

수정 방식:
- `G17ViewRenderer`에서 먼저 **G17 총기 전체 위치·yaw/pitch/roll 회전**을 동일하게 적용하고, 그 **자식 좌표로 오른손·왼손 위치/각도를 배치**합니다. 발사, 조준, 재장전에도 총과 손이 함께 움직입니다.
- 오른손잡이 기준 오른손은 화면 **총 오른쪽**, 보조 왼손은 총 **반대쪽 아래**에 둡니다. 왼손잡이는 반전됩니다.
- 보조 손은 ADS 또는 탄창을 다룰 때만 렌더링하고, 가늠쇠 시야를 덮지 않도록 팔 모델을 약 **0.69배**로 줄이고 총 아래쪽에 둡니다.
- 재장전 시 왼손은 총 기준 **+0.44 Y**까지 올라가 탄창 쪽에서 움직입니다.
- **기존 G17 3D 모델·총구 방향(-Z)·철가늠쇠 ADS 원점·슬라이드/탄창 모델 상태·장탄 수/발사/재장전 38틱·HUD·물리 탄환·AI 소음·3인칭**은 변경하지 않았습니다.
- Python CI 검증은 **총 기준점으로 손이 함께 이동/회전**하는지, 오른손은 오른쪽/왼손은 왼쪽인지, 모델이 너무 크게 배치되지 않았는지 확인합니다.

### 직접 테스트
1. 게임 완전 종료 → GitHub Desktop Fetch origin → Pull origin → IntelliJ `.\gradlew.bat runClient`.
2. **G17을 일반 1인칭에서 든 상태**: 오른손이 총 손잡이 오른쪽에 있고 총이 가려지지 않는지 확인합니다.
3. **우클릭 ADS**: 총의 뒷가늠쇠가 중앙이며 오른손이 왼쪽으로 넘어오지 않고, 왼손이 아래에서 받치면서 슬라이드를 덮지 않는지 확인합니다.
4. **R 재장전**: 보조 왼손이 총 쪽으로 올라오면서 탄창을 다루는 모습이 나타나는지 확인합니다.
5. **총성 발사/슬라이드 후퇴**, F5 **3인칭**, 17발·1.9초 재장전·HUD 유지 여부를 확인합니다.
